# ZZZ Queue OBS 新手使用手册

适用版本：v1.8.0 · 更新日期：2026 年 9 月 19 日

这份手册面向不懂编程的主播。先完成第 1–3 节，再根据设备选择一种接收方案：有副屏看第 4 节，没有副屏看第 5 节；接通后继续第 6 节，把队列放进直播画面。手机、抽奖、桌面悬浮窗等功能可以之后再设置。

**最重要的一句话：观众加入的是“接下来”；主播点击“完成当前叫号并继续”，才会把第一位观众变成“当前”，并进行语音叫号。**

## 1. 先认识这几个窗口

| 名称 | 用来做什么 | 观众是否需要看到 |
| --- | --- | --- |
| ZZZ Queue 主程序 | 保持排队服务运行，右下角有角色图标 | 不需要 |
| 排队控制台 | 设置房间、排队规则、抽奖、语音和手机连接 | 不要作为直播内容 |
| 直播面板 | 简化的日常操作页面，适合手机 | 不需要 |
| LAPLACE Chat 控制台 | 接收 B 站弹幕和礼物，再交给排队插件 | 不要直接展示设置页 |
| OBS 排队挂件 | 只显示当前观众和等待队列 | 按需展示 |
| OBS 弹幕挂件 | 把收到的聊天显示在直播中 | 可选，默认关闭 |
| 桌面悬浮窗 | 让主播在游戏上方看队列、弹幕并操作 | 取决于 OBS 的捕获方式 |

LAPLACE Chat → 本机桥接 → 排队插件 → OBS 挂件 / 桌面窗 / 手机。

你不需要理解“桥接”的技术原理。把它理解为两边传递弹幕的小通道即可。**本插件的完整安装包已经带了桥接程序，不需要安装 Docker。**

本工具不是放进 OBS 插件目录的 DLL。它是独立运行的 Windows 程序，OBS 通过“浏览器”来源显示它的挂件。普通使用不需要开启 OBS WebSocket，也不需要填写 OBS 密码。

## 2. 下载、解压和第一次启动

### 2.1 推荐下载 EXE 版

1. 打开 [官方下载页](https://github.com/Karl-Cao/zzz-queue-obs/releases/latest)。
2. 找到 **Assets**，它的意思是“可下载的文件”；没有展开就点击展开。
3. 下载名称以 **windows-x64-exe.zip** 结尾的文件。例如 `obs-queue-1.6.1-windows-x64-exe.zip`。
4. 不要选择 `Source code (zip)`，那是开发用源码，不是普通用户的安装包。
5. 在下载文件上点击右键，选择 **全部提取 / 解压到**。
6. 放到一个以后不会随手删除的文件夹，例如 `D:\直播工具\ZZZ Queue`。没有 D 盘也可以放在自己的“文档”文件夹。
7. 打开解压后的文件夹，双击 **ZZZ Queue.exe**。

请先解压再运行。不能直接在压缩包窗口里启动，也不能只把 EXE 拖出来、丢掉其他文件夹。可以为 EXE 创建桌面快捷方式；快捷方式和只复制 EXE 是两回事。

EXE 版无需另外安装 Python、Node.js 或 Docker。若 Windows 提示未识别的应用，请先核对下载来源是否为上面的仓库；不要为了运行插件而关闭整台电脑的安全防护。

### 2.2 启动成功是什么样

正常情况下，浏览器会打开排队控制台，Windows 右下角出现你熟悉的角色图标。找不到图标时，点击时钟附近的 **向上箭头 / 隐藏的图标**。

第一次启动请耐心等候；慢电脑最多会等待约 90 秒。不要连续解压多个副本、反复启动不同目录里的程序。

点击托盘图标可重新打开控制台。关掉排队控制台的浏览器标签页，不等于关闭主程序。

控制台顶部会显示本副本的版本、地址和运行目录（目录仅在电脑本机显示）。打开页面时会检查常用端口 3667–3766；发现其他副本会列出它们的地址和版本。核对 OBS 来源所用地址，退出不用的旧副本。检查不会擅自停止其他程序，自定义范围外端口不在此检查范围内。

### 2.3 Python 版给谁用

如果你只想直播，选 EXE 版即可。Python 版适合已有 Python、想修改启动源码的用户：下载 `windows-x64-python.zip`，完整解压，安装 Python 3.10 或更新版本，再运行 **start-python.cmd**。首次运行需要联网安装依赖。两版功能一致，不需要同时运行。

## 3. 在排队插件里填写基本设置

打开排队控制台，找到 **连接与规则**。如果手机样式的页面里找不到设置，先点顶部的 **设置控制台**。

第一次建议这样填：

| 项目 | 建议填写 | 说明 |
| --- | --- | --- |
| 直播间 ID | 你自己的 B 站直播间数字 | 不是 B 站账号 UID，也不是个人空间地址 |
| 桥接地址 | `ws://127.0.0.1:9696` | 新安装使用这个默认值 |
| 桥接令牌 | 留空 | 两边都没设密码时都留空 |
| 排队口令 | `排队` | 观众需要完整发送这个口令 |
| 最低礼物金额（元） | `0.1` | 不能低于 0.1 元 |
| 抽奖口令 | `抽奖` | 建议与“排队”不同 |
| 抽奖时长（秒） | `60` | 倒计时一分钟 |
| 开放排队 | 勾选 | 允许正常入队 |
| 在 OBS 弹幕源中展示聊天 | 先不勾选 | 后面需要展示弹幕时再开 |

填完点击 **保存设置**。然后在“接下来”卡片勾选 **开启免费排队**，方便第一次测试。

例如你的直播间网页是 `https://live.bilibili.com/446277`，通常填写 `446277`。这里是演示号码，其他主播要换成自己的房间。少数房间有短号和真实房间号之分；如果 LAPLACE 有弹幕、插件始终不认房间，请核对 LAPLACE 实际连接的房间数字是否与插件一致。

### 3.1 三种地址不要混用

| 地址示例 | 填在哪里 |
| --- | --- |
| `http://127.0.0.1:3667` | 电脑浏览器打开排队控制台 |
| `ws://127.0.0.1:9696` | LAPLACE 和排队插件各自的“桥接地址” |
| `http://192.168.1.20:3667/live` | 手机浏览器；实际地址从电脑控制台读取 |

`3667` 是默认的网页端口；被占用时程序会换一个数字。后续请使用实际控制台地址。`9696` 是桥接端口，与网页端口不是同一个东西。**不要因为网页是 3667，就把桥接地址也改成 3667。**

旧配置可能使用 `9698`，本插件也支持自动启动它；已有连接正常就不必更改。`9697` 不是本插件默认自动启动的桥接端口。

### 3.2 根据显示器选择一种接收方案

**第 4 节和第 5 节是两种替代方案，只选一条路线，不需要两套都做。**

| 你的设备 | 接下来怎么做 |
| --- | --- |
| 有副屏，能在副屏一直显示 LAPLACE | 按第 4 节设置，完成后跳过第 5 节，继续第 6 节 |
| 没有副屏，只有一个显示器或笔记本屏幕 | 跳过第 4 节，直接按第 5 节在 OBS 内设置，完成后继续第 6 节 |

两种方案都需要运行排队主程序。手机是可选的遥控器，不负责接收弹幕。

## 4. 方案一：有副屏，在副屏运行 LAPLACE Chat

**适合有副屏的用户。** 将 LAPLACE 控制台放在副屏，主屏用来玩游戏。本节完成后直接前往第 6 节，不需要再配置第 5 节的 OBS 接收端。

### 4.1 先让 LAPLACE 本身收到弹幕

1. 在直播电脑打开 [LAPLACE Chat](https://chat.laplace.live/)。
2. 在首页选择连接方式，并填入自己的直播间号或直播间链接。
3. 对于排队这种要区分“是谁”的功能，优先使用能提供可靠观众身份的连接方式。幻星连接不能提供真实 UID，不能只凭“能看到昵称”就认定排队身份一定正确。[LAPLACE 控制台说明](https://laplace.live/chat/dashboard)
4. 在首页底部点击 **打开控制台**。
5. 用手机进入 B 站直播间，发送一条容易辨认的普通弹幕，例如 `连接测试01`。
6. 先确认这条弹幕出现在 **LAPLACE 控制台**，再进行下一步。

如果 LAPLACE 本身没有收到，先处理它的房间号、登录或网络问题。此时修改排队插件的规则不会解决问题。

### 4.2 开启 Event Bridge

确认排队主程序已经启动，再在 **LAPLACE 控制台** 操作：

1. 点击右上角的 **设置 / 齿轮**。
2. 在设置面板内向下滚动，找到 **Event Bridge**。不同 LAPLACE 版本可能把它放在高级或实验功能相关区域；要找的是这个名称，不是 Event Fetcher。
3. 开启 Event Bridge。
4. 地址填入 `ws://127.0.0.1:9696`。如果插件已经使用 9698，两边都使用 9698。
5. Token / 令牌与排队插件完全一致；新安装没设令牌时，两边都留空。
6. 按页面提供的连接按钮连接，或等待开启后自动连接。
7. 回到排队插件，查看 **LAPLACE Event Bridge** 卡片。如有需要，点 **重新连接 / 启动桥接**。

默认桥接由本工具启动。普通用户不用另下一个桥接程序，也不需要安装 Event Fetcher。官方桥接的默认端口和可选认证机制见 [Event Bridge 说明](https://laplace.live/chat/event-bridge)。

### 4.3 完整验收：一定要再发一条真实消息

1. 在手机的 B 站直播间发送 `连接测试02`。
2. 确认 LAPLACE 收到了。
3. 确认排队插件的 **弹幕与礼物** 区域也出现了它。
4. 查看插件的“已收到……条事件 / 最近……”是否更新。
5. 再发送 `排队`，确认自己进入 **接下来**，而“当前”仍为空。

完成这些才算接通。**两边显示“已连接”但没有新消息，只能说明连接存在，不能说明弹幕正在传过来。**

如果免费排队关闭，普通 `排队` 弹幕不入队是正常规则，不代表桥接坏了。

### 4.4 直播时保持副屏浏览器活跃

把 `chat.laplace.live` 加入 Chrome / Edge 的“始终保持活跃”列表，并让 LAPLACE 保持为独立窗口中的当前标签页。官方说明指出：休眠例外不能完全消除后台计时器限制，切标签、最小化或被完全遮住仍可能影响接收。直播时让这个窗口持续显示在副屏，不要切走它的标签页。[浏览器后台限制说明](https://laplace.live/chat/dashboard)

配置完成后发一条真实弹幕确认插件收到，再直接前往第 6 节。

## 5. 方案二：没有副屏，在 OBS 内运行 LAPLACE Chat

**适合只有一个显示器或笔记本屏幕的用户。** 直接按本节操作，不需要先做第 4 节。OBS 保持 LAPLACE 来源运行；主播用桌面悬浮窗或手机控制排队。

### 5.1 建立一个专用的接收来源

1. 打开 OBS，选择平时直播游戏用的场景。
2. 在 **来源** 区域点击 **＋** → **浏览器**。
3. 新建来源，命名为 **LAPLACE 接收端—不要展示**。
4. 不勾选“本地文件”。URL 填入你的 LAPLACE 控制台地址，例如 `https://chat.laplace.live/dashboard/446277`。请换成自己的房间号。
5. 宽度可先填 `1280`，高度 `900`，便于设置时操作。这是本手册的起始尺寸，可自行调整。
6. **取消勾选“不可见时关闭源 / Shutdown source when not visible”。**
7. 建议也取消“场景激活时刷新浏览器”，避免切场景时反复重新加载。
8. 确定后，右键这个来源 → **交互**。
9. 在交互窗口里确认 LAPLACE 连接的是自己的直播间。用手机发一条 `连接测试01`，先确认 LAPLACE 自己能收到。
10. 在交互窗口内点击 LAPLACE 右上角的 **设置 / 齿轮**，向下找到 **Event Bridge** 并开启。
11. 桥接地址填 `ws://127.0.0.1:9696`；如果排队插件使用 9698，这里也用 9698。令牌与排队插件一致，没设令牌时两边留空。
12. 按页面的连接按钮或等待自动连接。回到排队插件，必要时点击 **重新连接 / 启动桥接**。
13. 从手机发送 `连接测试02`，确认它同时出现在 LAPLACE 和排队插件的“弹幕与礼物”区域。仅看到“已连接”不算验证完成。

OBS 的浏览器环境与 Chrome / Edge 不是同一份本地存储。请在 OBS 交互窗口内检查房间和连接设置；即使普通浏览器已配置过，这里仍需确认。若需要先在 LAPLACE 首页选择连接方式，可暂时将来源 URL 改为 `https://chat.laplace.live/`，在“交互”里配置后打开自己的控制台。

如果选择使用 LAPLACE 首页生成的带配置控制台链接，请使用页面实际提供的链接；不要手工拼接同步密钥参数。含同步密钥的链接请保密。[LAPLACE 配置链接说明](https://laplace.live/chat/obs-setup)

### 5.2 让它运行，但不把后台设置播出去

在 OBS 来源列表中，**越靠上的来源，画面越在前面**。建议按下面顺序排列：

1. OBS 排队挂件 / 可选的弹幕挂件。
2. 游戏捕获。
3. 一张铺满画布的不透明“颜色源”，例如黑色，作为遮挡底板。
4. LAPLACE 接收端—不要展示。

颜色源可以通过“来源 → ＋ → 颜色源”创建。它应放在游戏下方、LAPLACE 上方；这样游戏没打开时，LAPLACE 控制台也不会从后面露出来。确认预览后锁定这些来源，减少误拖动。

**保持 LAPLACE 接收端的眼睛图标开启，并保留在当前活动场景中。** 不要用关闭眼睛作为本流程的遮挡方式；使用上面的不透明来源遮挡。OBS 官方说明：启用“不可见时关闭源”会卸载页面，场景激活刷新也会重新加载。[OBS 浏览器来源说明](https://obsproject.com/kb/browser-source)

有多个直播场景时，使用“添加现有来源”复用这个接收端，并在每个相关场景放好遮挡底板。不要新建多个不同的 LAPLACE 接收端，让它们同时重复转发同一房间。

### 5.3 做一次后台测试

1. 用 OBS 的“交互”确认 LAPLACE 桥接已连接。
2. 从手机发送 `后台测试01`，确认排队插件收到。
3. 关闭交互窗口，切回游戏。不要关闭 OBS。
4. 从手机发送 `后台测试02`，在手机排队面板或桌面悬浮窗中确认出现。
5. 切换到平时会用的另一个 OBS 场景，再发送 `后台测试03`。

这套流程已有短时测试依据；不同 OBS 版本、显卡和场景设置仍需在自己的电脑上验证。准备长时间直播前，按平时的游戏方式运行一段时间，期间发送几条编号消息检查是否持续收到。

### 5.4 每次直播保持这套方案运行

1. 启动排队主程序，再打开 OBS。
2. 确认当前场景包含配置好的 LAPLACE 接收端，来源没有关闭。
3. 发一条真实弹幕，确认手机面板或桌面悬浮窗收到。
4. 保持 OBS 运行，就可以切回游戏；不需要另开第 4 节的副屏浏览器接收方案。

接下来前往第 6 节，添加观众看到的排队挂件。这里的 LAPLACE 接收端负责收消息，第 6 节的挂件负责展示队列，用途不同。

## 6. 把排队和弹幕放进直播画面

### 6.1 添加排队挂件

1. 在排队控制台找到 **OBS 排队挂件** 链接，打开它并复制浏览器地址栏中的完整地址。
2. 回到 OBS 的游戏场景，在“来源”点 **＋ → 浏览器**。
3. 新建来源，命名为 **ZZZ 排队**。
4. 把刚复制的地址粘贴到 URL，不勾选“本地文件”。
5. 宽度先设 `360`，高度先设 `400`，之后根据自己的直播布局调整。
6. 确定，将它拖到画面合适位置，并放在来源列表的游戏捕获上方。
7. 用 OBS 预览检查名字、金额和“当前 / 接下来”是否清楚，再锁定来源。

默认端口时，中文挂件地址示例为 `http://127.0.0.1:3667/overlay?lang=zh`。英文用 `lang=en`。**优先复制插件实际提供的链接，不要照抄端口示例。** OBS 挂件顶部固定显示当前观众，下方展示全部等待名单。控制台“连接与规则”中的 **OBS 排队显示模式（自适应尺寸）** 可选择“自动翻页”或“自动滚动”，点击保存后挂件会同步更新。

- **自动翻页（默认）**：根据来源高度自动计算每页人数，默认每 6 秒换一页（可调 3–30 秒），末页后回到第一页。360×400 通常每页约 4 人；加高来源可以显示更多人。
- **自动滚动**：名单缓慢向上滚动，顶部和底部各停留 2 秒，滚到底后回到顶部。
- 等待名单在当前高度下能够全部容纳时，两种模式都保持静止。
- 手动叫下一位时回到开头；普通新增、礼物重排尽量保留正在观看的位置，例行状态同步不会重置进度。调整字体、速度或来源尺寸时会重新开始。
- 在 OBS 浏览器来源的“属性”中修改宽度和高度，挂件会自动重新排版。只在画布上拖动缩放不会改变每页人数。当前观众保持固定，等待区域利用剩余高度。
- 显示真实名次、昵称、金额和中奖星标，隐藏 UID。长昵称会省略，主播可在控制台查看。

如果看到的是一整页设置按钮，说明填成了控制台地址；请改用上面带 `/overlay` 的挂件链接。

“连接与规则”还可设置 **翻页间隔（3–30秒）**、**滚动速度（5–60像素/秒）**、**名单字号（12–24）** 和 **挂件显示金额**。保存后同步到挂件。字体越大，每页可容纳人数越少；隐藏金额可以给昵称更多空间。

### 6.2 选择是否让观众看到弹幕

不想把弹幕播出去：不添加 OBS 弹幕来源，并保持 **在 OBS 弹幕源中展示聊天** 关闭。桌面窗和手机仍可用于自己看消息。

想把弹幕播出去：

1. 在排队控制台“连接与规则”勾选 **在 OBS 弹幕源中展示聊天**。
2. 点击 **保存设置**。
3. 打开控制台中的 **OBS 弹幕挂件** 链接，复制完整地址。
4. OBS 新建“浏览器”来源，命名为 **ZZZ 弹幕**，粘贴这个地址。
5. 可先用 `500 × 700` 的尺寸，按预览调整。
6. 发送新弹幕检查。没有消息，或者开关没开时，空白是正常现象。

本插件的弹幕来源是简化显示，不等于 LAPLACE 官方所有模板、动效和礼物展示功能。如果你另外使用 LAPLACE 官方 OBS 链接，就在 LAPLACE 首页配置并复制它；建议只选择一种观众弹幕显示方式，避免同一条消息出现两份。

关闭本插件的聊天开关，只会关闭本插件 `/chat-overlay` 的输出，不会关闭你另外添加的 LAPLACE 官方弹幕来源。

## 7. 排队规则与日常叫号

### 7.1 免费排队

在“接下来”区域打开 **开启免费排队**。观众发送完整的排队口令，例如 `排队`，就会加入等待队列。重复发送不会增加同一 UID 的队列名额。

`我要排队` 和 `排队呀` 不等于 `排队`。如果你修改了口令，记得把新口令告诉观众。

关闭免费排队后，普通口令不再让观众加入；之前已经在队列里的人不会因此自动移除。

### 7.2 礼物排队与累计排序

符合最低金额的付费礼物可直接入队，不需要再发送排队口令。金额在等待期间按观众累计；累计越高，排得越前。同额时先入队的人优先。免费礼物和银瓜子不计入付费金额。

| 发生的事 | 等待队列 |
| --- | --- |
| A 送 1 元 | A：1 元 |
| B 送 2 元 | B：2 元，A：1 元 |
| A 再送 2 元 | A：3 元，B：2 元 |
| 主播点击继续 | A 进入“当前”，B 留在等待队列 |
| B 再送礼 | B 的等待金额继续累计，不会挤掉当前 A |

最低金额按**每次收到的有效礼物事件金额**判断。比如最低设成 1 元，多次单独发送、每次只有 0.1 元的事件不会自动凑到 1 元入队；有效事件入队后才参与累计。

### 7.3 正确使用“当前”与“接下来”

1. 第一次开始服务观众时，点击 **完成当前叫号并继续**。
2. 等待第一位进入“当前”；开启电脑 TTS 时会叫号一次。
3. 为当前观众完成游戏、组队或其他约定操作。
4. 完成后再点击同一个按钮，上一位进入完成历史，下一位变成当前。

等待队列为空时，点击继续只会完成当前，不会再叫一个不存在的人。

**重播当前叫号**：再叫一次当前观众，不推进队列。

等待行的 **移除**：把该观众直接移出等待队列，不会先叫到当前。误点后可在控制台“当前”卡片点击 **撤销上次操作（20秒内）**。同样可撤销“完成当前叫号并继续”。只支持最近一次操作；过期、重启或状态冲突后不能撤销。撤销不会重新播报，但不能收回已经听到的叫号；之后的新入队和有效礼物会保留。

当前观众的再次排队或送礼不会让其同时出现在等待队列；完成后可重新参加，新一轮重新计金额。队列显示的金额不是该观众终身消费总额。

### 7.4 暂停入队、暂停聊天有什么区别

| 操作 | 实际作用 |
| --- | --- |
| 取消“开放排队”并保存 | 暂停正常的口令与礼物入队；保留已有队列，仍可叫号 |
| 关闭“开启免费排队” | 禁止免费口令入队，仍允许符合门槛的礼物 |
| “暂停滚动” | 暂停本页面消息区的显示更新，不停止接收，不停止排队 |
| “取消”抽奖 | 停止当前抽奖；不是清空普通队列 |

“开放排队”开关不取消已开启的抽奖。需要两者都暂停时，分别暂停排队并取消抽奖。

## 8. 抽奖：口令或礼物报名

### 8.1 先设规则，再开抽奖

在“连接与规则”设置并保存：

- **抽奖口令**：例如 `抽奖`。不想与普通排队一起触发，就不要与排队口令设成一样。
- **抽奖时长**：例如 `60` 秒；可设置 5–86400 秒。
- **允许礼物参加抽奖**：不想让礼物报名就取消勾选。
- **抽奖礼物名称**：填写实际礼物的完整名字，不填写 ID；同名不同 ID 的礼物都可匹配。留空表示任意达到金额门槛的有效礼物。
- 礼物报名使用同一“最低礼物金额”门槛。

礼物名可从收到的礼物记录确认。当前控制台不提供房间礼物图鉴。礼物报名和口令报名是“任选一种”，不是“必须送礼后再发口令”。

### 8.2 开始与结束

1. 在 **幸运观众** 区域点击 **开启抽奖**。
2. 把报名口令、礼物规则和剩余时间告诉观众。
3. 开启之后，观众发口令或送符合规则的礼物才能报名。
4. 每位观众在同一轮只有一份报名资格；重复发送不会增加抽中权重。
5. 倒计时结束后自动开奖；也可以点 **立即开奖** 提前结束。
6. 想中止这一轮就点 **取消**。

抽奖开启时会记住这一轮的规则；中途改设置不改变正在进行的一轮。想用新规则，请取消后重新开启。没有报名者时会结束，不产生中奖者。

### 8.3 中奖后会怎样

中奖者进入 **接下来第一位**，不会自动打断当前观众，也不会自动叫号。主播点击“完成当前叫号并继续”时才轮到中奖者。

中奖者优先于普通礼物排序；后续新的中奖者会排在之前中奖者前面。已经在普通等待队列里的中奖者会在原条目上置顶，不额外复制一行。当前观众不会再次被抽中进入等待队列。

符合普通礼物排队规则的礼物，也可能同时让观众进入普通队列和本轮抽奖报名。未中奖并不等于从普通队列移除。免费排队关闭时，抽奖口令报名仍然有效。

## 9. 设置叫号语音，并确认观众听得见

TTS 就是“让电脑把文字读出来”。这里有两套独立语音：

| 语音 | 在哪里设置 | 什么时候说话 |
| --- | --- | --- |
| 排队叫号 | 本插件“语音播报” | 主播手动继续或重播当前 |
| LAPLACE 弹幕播报 | LAPLACE 自己的设置 | 按 LAPLACE 规则读弹幕与礼物 |

### 9.1 开启电脑叫号

1. 在排队控制台的“连接与规则”选择 **叫号语音语言：中文 / English**，保存。
2. 在“语音播报”勾选 **电脑后台 TTS**。
3. 等状态显示语音就绪。
4. 点击 **测试电脑语音**。
5. 确认耳机或扬声器里听到了测试句。

电脑后台 TTS 使用 Windows 安装的语音，不依赖排队控制台标签页一直显示。切换界面语言不会自动改变叫号语言；两者分别设置。

**启用此设备 TTS** 是浏览器播报的备用方式，不是必点按钮。电脑后台 TTS 开启时，不要再让手机也播一份。浏览器方式还可能受标签页休眠或自动播放限制影响。

### 9.2 检查 OBS 是否录到了声音

1. OBS 的混音器里，确认用于采集电脑声音的音频来源没有静音。
2. 点击“测试电脑语音”，观察对应音量条是否跳动。
3. 做一段十几秒的 **本地录制**，不用正式开播。
4. 停止录制并播放文件，确认里面能听到叫号。

如果你平时只捕获游戏应用的声音，叫号可能不会被游戏音轨收进去。请让 OBS 采集 TTS 实际输出的电脑音频设备。避免同时用两条来源重复捕获同一份电脑声音，否则可能有回声。

### 9.3 如果还想让 LAPLACE 读弹幕

在 LAPLACE 控制台的设置面板中开启它自己的 TTS，并按所选服务配置声音。首次建议先验证本插件叫号，再添加弹幕播报，容易判断声音来自哪里。[LAPLACE TTS 官方说明](https://laplace.live/chat/tts)

手动叫号能避免“刚入队就自动说话”，但**不会自动暂停 LAPLACE 正在读的弹幕**。希望完全避开重叠时，可关闭 LAPLACE 弹幕 TTS，或等它读完再手动叫号。

## 10. 用桌面悬浮窗边玩边操作

1. 右键主托盘图标，选择 **打开桌面悬浮窗**。
2. 屏幕上会出现队列与聊天窗口。默认是鼠标穿透：点击会落到后面的游戏，不会点中悬浮窗。
3. 需要操作时，同时按 **Ctrl + Alt + Q**。
4. 进入操作模式后，可点 **完成当前并继续、重播、抽奖、开奖、语音测试、控制台**，也可移除等待观众。
5. 在操作模式拖动顶部标题，把窗口移到合适的位置。
6. 操作完，再按 **Ctrl + Alt + Q** 返回穿透模式。
7. **Ctrl + Alt + H** 隐藏或重新显示悬浮窗。

快捷键被其他程序占用时，可通过悬浮窗自己的托盘菜单切换模式。主程序和悬浮窗各有托盘入口：悬浮窗菜单“退出悬浮窗”只关它；主程序菜单“退出并停止服务”才是完整退出。

游戏建议使用 **无边框窗口 / 窗口化**。独占全屏模式可能把悬浮窗挡住。

如果不想让观众看到悬浮窗，优先用 OBS 的 **游戏捕获** 并实际检查录制。**显示器捕获** 会录整块屏幕，通常也会把悬浮窗录进去。关闭“OBS 弹幕输出”不能隐藏已经被显示器捕获拍到的窗口。

## 11. 用手机或平板管理排队

手机只负责遥控，不需要安装本插件，也不需要在手机上设置桥接。

1. 保持直播电脑上的主程序运行。
2. 电脑和手机连接同一个家庭 / 工作室局域网。电脑用网线、手机用同一路由器 Wi-Fi 也可以。
3. 在插件文件夹里运行 **enable-lan.cmd**。Windows 询问管理员授权时允许它为本插件添加局域网访问规则。
4. 在电脑排队控制台找到 **手机 / 平板控制**。
5. 将显示的完整地址输入手机浏览器，例如 `http://192.168.1.20:3667/live`。
6. 按提示输入电脑上显示的 **八位配对码**。
7. 手机出现队列与控制按钮后，就可以操作叫号、抽奖等功能。

手机不能填写 `127.0.0.1` 或 `localhost`：在手机上，它们表示手机自己，不是直播电脑。也不要在手机地址栏里输入 `ws://…:9696`。

配对会话约 12 小时有效；重启服务后可能需要重新配对。换 Wi-Fi、路由器重启、电脑地址改变后，重新查看电脑控制台的地址，不要一直使用旧收藏。

如果有多个地址，先试与你手机处于同一家庭 Wi-Fi 网段的地址；不要优先选 VPN 或虚拟网卡地址。访客 Wi-Fi 可能禁止设备互相访问，需要换普通 Wi-Fi。

手机去刷视频、切到其他应用，不会停止电脑后台排队和叫号。回来后刷新页面即可查看最新状态；不要依赖手机浏览器后台 TTS 来承担电脑叫号。

## 12. 不花钱演练一次完整流程

请在**没有真实观众排队时**进行。模拟功能会写入正在使用的真实队列，不是隔离练习场。

1. 打开免费排队，确认当前和等待队列都没有要保留的人。
2. 找到 **模拟弹幕 / 礼物**。
3. UID 填 `900001`，昵称填 `测试A`，弹幕填实际排队口令，点击 **发送弹幕**。
4. 确认 A 出现在“接下来”，当前仍为空，电脑不会自动叫号。
5. 改 UID 为 `900002`、昵称 `测试B`，金额填 `2`，点击 **赠送礼物**。
6. 确认 B 因有效礼物金额排在免费 A 前面。
7. 点击 **完成当前叫号并继续**：B 进入当前；电脑 TTS 开启时应播报 B。
8. 开启抽奖，换第三个测试 UID，发送实际抽奖口令，点击 **立即开奖**。
9. 确认中奖者在等待第一位，当前 B 没有被挤掉，也没有自动叫号。
10. 完成后移除剩余测试等待条目；当前若仍是测试用户且等待队列已空，再点一次“完成当前叫号并继续”结束它。

模拟测试通过，只能证明本插件规则和播报正常；它不验证 LAPLACE 是否真正接通。开播前仍需发送一条真实 B 站弹幕。

## 13. 每次开播与下播怎么做

### 开播前

1. 启动 `ZZZ Queue.exe`，确认托盘存在。
2. 有副屏：保持副屏 LAPLACE 控制台运行；无副屏：打开 OBS，让第 5 节的 LAPLACE 接收端运行。
3. 检查插件的房间号、排队开关和最低金额。
4. 从手机发一条编号测试弹幕，确认插件收到。
5. 点击“测试电脑语音”，观察 OBS 音量条；第一次使用或换设备后做一次本地录制。
6. 检查 OBS 预览：只有打算播出的挂件，没有配对码、同步密钥或后台设置页。
7. 打开桌面悬浮窗或手机面板，再正式开播。

### 直播中出现异常

先看本手册第 15 节。需要重启时，在**主托盘**右键选 **重启服务**。它会先停止旧服务，再启动；不要立即又启动另一个版本。慢机器等待就绪后再测试新弹幕。

重启会短暂断开控制台、手机和桥接。重新配对或重新连接后发送新弹幕验证；断开期间错过的事件不能假定会自动补回。

### 下播后

1. 结束直播。
2. 在主托盘选择 **退出并停止服务**。
3. 确认主托盘图标消失。
4. 再按需关闭 OBS 与 LAPLACE 页面。

仅关闭悬浮窗或排队网页不会停止主服务。反过来，承担接收任务的 LAPLACE 页面若关闭，真实弹幕来源就可能中断。

## 14. 升级、换文件夹与保留数据

1. 先退出主托盘和旧悬浮窗，并停止旧版本服务。
2. 下载新版本，解压到新文件夹。
3. 在旧文件夹里找到整个 **data** 文件夹，复制到新版本的主目录。
4. 启动新版本。不要同时启动旧版。
5. 检查房间号、队列、语音、OBS 链接和手机地址。
6. 如果手机连接失败，重新运行新目录的 `enable-lan.cmd`。

`data` 保存设置与队列。备份时先停服务，复制整个文件夹；不要编辑里面看不懂的文件。`data` 可能包含令牌和观众记录，不要把整份上传到公开仓库或问题反馈中。

v1.6.x 会保存“当前”和等待队列。由更早、尚无“当前”概念的版本升级时，旧队列保留为等待队列，不会自动叫号。重启不是清空队列的方法。

## 15. 常见问题：按症状排查

### A. 双击 EXE 没看到控制台

先展开 Windows 右下角隐藏图标，看看主程序是否已在运行。点击图标打开控制台；没有图标则检查是否完整解压、有无被移动的配套文件。启动失败提示出现后，不要只留 EXE 再试。可查看 `data/tray-error.log` 和 `data/server-error.log` 的最近错误。

### B. LAPLACE 连接 9697 一直失败

新安装两边改成 `ws://127.0.0.1:9696`，保存后在插件点击“重新连接 / 启动桥接”，再回 LAPLACE 连接。已有 9698 配置可以两边统一为 9698。确认输入的是 `ws://`，不是网页的 `http://`，也不是手机局域网地址。

### C. 两边都显示已连接，但排队插件没消息

先发新消息，看 LAPLACE 自己是否收到。收到了，再检查它的 Event Bridge 开关、地址、令牌和插件房间号。普通浏览器设置好，不代表 OBS 交互窗口也设置好了。只保留一个选定的接收端转发该房间。

### D. 插件能显示弹幕，但发送“排队”不入队

检查“开放排队”是否开启、免费排队是否开启、口令是否完全相同、该观众是否已经在等待或当前。免费排队关闭时，需有效付费礼物或符合抽奖流程。

### E. 礼物不计入 / 名次不对

检查是否付费礼物、是否达到单次事件的金额门槛、是否来自正确房间。当前观众不会因再次送礼挤入等待队列；中奖置顶也会优先于普通金额排序。排除规则原因后，记录发生时间、礼物名和数量，以便反馈。

### F. 中奖后没叫号

这是设计行为。中奖者先进入“接下来”，主播点击“完成当前叫号并继续”才会叫号。

### G. 电脑听不到叫号

先打开“电脑后台 TTS”，等待就绪并点测试；检查 Windows 输出设备和音量。只有手动继续 / 重播才叫号，普通进队不叫号。语音不可用时，在 Windows 设置中搜索“语音”，检查相应语言语音是否安装，再重启插件。

### H. 电脑能听到，观众听不到

看 OBS 音量条并本地录制。仅采集游戏音频时可能漏掉 Windows 叫号；确认捕获的是实际播放 TTS 的音频设备，且对应输出音轨用于直播。

### I. 两个声音同时读、或者有回声

区分电脑后台 TTS、手机 / 浏览器 TTS、LAPLACE 弹幕 TTS。叫号优先只保留电脑后台 TTS。回声还应检查 OBS 是否重复捕获同一音源。手动叫号不会自动暂停独立的弹幕播报。

### J. 悬浮窗点不动 / 游戏挡住它

点不动先按 Ctrl+Alt+Q 切操作模式。看不到先按 Ctrl+Alt+H，再检查游戏是否为独占全屏；切无边框窗口后测试。快捷键冲突时使用悬浮窗托盘菜单。

### K. 手机打不开、一直连接失败

确认主服务运行、手机使用控制台显示的局域网 `http://` 地址、连接同一路由器、已执行 `enable-lan.cmd`，并排除访客 Wi-Fi 隔离。重启或换网络后重新查看地址和配对码。不要输入 `127.0.0.1`。

### L. OBS 弹幕来源一片空白

先展开控制台“弹幕与礼物”下面的 **弹幕诊断预览（仅主播）**。它会区分输出开关关闭、桥接未连接、尚无事件、收到事件但本房间没有聊天等状态，并预览最近消息。该区域只在已授权控制台显示，不会添加到 OBS 挂件，也不会注入模拟消息。

先在插件开启“在 OBS 弹幕源中展示聊天”并保存，再发新消息。确认 URL 是 `/chat-overlay`，且端口与控制台一致。默认关闭或暂时没有消息时，空白正常。

### M. 一切正常，切标签 / 切场景后就断了

检查真正负责接收的 LAPLACE 页面是否被后台挂起或卸载。副屏浏览器按第 4.4 节处理；OBS 按第 5 节检查来源存活设置和各场景配置。排队网页关掉与 LAPLACE 接收页面关掉不是一回事。

### N. 问题仍未解决，怎样反馈

到 [GitHub Issues](https://github.com/Karl-Cao/zzz-queue-obs/issues) 说明：插件版本、EXE 还是 Python 版、Windows / OBS 版本、在哪一步失败、LAPLACE 是否能收到新消息、插件是否有新事件，以及完整错误文字。截图前遮住同步密钥、桥接令牌和配对码；不要直接上传整个 `data` 文件夹。

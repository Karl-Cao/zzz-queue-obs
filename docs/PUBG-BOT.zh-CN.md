# PUBG 端游查询

本功能在公共机器人服务器运行，主播端无需更新、无需重新绑定群。群内真正 @机器人后输入 `/pubg帮助`。它使用 PUBG 官方 API，不需要群成员提交 Cookie、扫码或安装插件。

## 群成员使用

| 口令 | 用途 |
| --- | --- |
| `/pubg帮助` | 查看简明说明与绑定示例 |
| `/pubg绑定 游戏昵称` | 默认 Steam；通过官方昵称查询保存 Account ID |
| `/pubg绑定 xbox 游戏昵称` | 指定平台；也支持 steam、kakao、psn |
| `/pubg查询` | 查看生涯场次、吃鸡次数、KD、场均伤害 |
| `/pubg排位` | 查看当前赛季各有数据模式的段位、分数、KDA、场均伤害 |
| `/pubg最近比赛` | 从官方仍提供的比赛记录中按时间排序，展示最新十场 |
| `/pubg解除绑定` | 仅删除发起者自己的 PUBG 查询目标 |

示例：先发 `/pubg绑定 YourGameName`，再发 `/pubg查询`。请替换 YourGameName 为游戏内昵称。重新绑定可切换目标，查询失败不会覆盖旧绑定。不同 QQ 成员绑定互相隔离；这是查询偏好，不是账号所有权验证。

不支持 PUBG Mobile 或和平精英。绑定保存的是 PUBG Account ID，不是 Steam 的数字 ID。生涯与排位数据缓存五分钟，玩家近期记录一分钟，赛季列表一小时，比赛详情三十分钟；未结束的比赛可能尚无数据。普通战绩的 KD 以击杀 /（场次 − 吃鸡次数）计算，无死亡场次显示“—”；排位展示官方 KDA。比赛时间标明 UTC。

近期比赛 ID 不假设有时间顺序。最多读取100条比赛详情、最多四条并发，45秒后停止等待，按读取到的真实时间排序；若记录超过上限、部分失效或超时，回复明确说明是本次成功读取的记录中最新十场。

## 运营者部署

1. 在 [PUBG 开发者平台](https://developer.pubg.com/) 注册应用并申请 API Key，按平台要求填写用途。不要把密钥发到群里或提交到 Git。
2. 在服务器 `/etc/zzz-public-qq.env` 设置 `PUBG_API_KEY`，随后仅重启 `zzz-public-qq-bot`。早柚核心与主播端无需重启。
3. 绑定保存于 `/var/lib/zzz-public-qq/pubg.sqlite3`，升级保留这个文件。其他部署路径可用 `PUBLIC_QQ_PUBG_DB` 覆盖；服务用户必须对所在目录有写权限。
4. `/pubg帮助`、解除绑定及未绑定提示不依赖 API Key；缺少或无效密钥时，查询明确提示管理员配置，不要求玩家提供凭据。

每个进程对需要授权的 API 采用每分钟最多10次的保守限流；429后暂停一分钟，不自动重试。命中缓存不占额度。比赛详情按官方说明无需 API Key，不发送 Bearer。缓存有容量上限，重启只清除缓存，不清除绑定。同一 Key 不应由多个进程同时独立消耗额度；若另有应用共用，需统一配额。

QQ 口令面板只新增 `/pubg帮助` 入口，其余口令在帮助中展示。现有排队及 ZZZ、原神、LOL 指令不会被 PUBG 转发到早柚核心或排队中转。

来源：[官方入门](https://documentation.pubg.com/en/getting-started.html)、[API Key](https://documentation.pubg.com/en/api-keys.html)、[官方比赛接口定义](https://github.com/pubg/api-documentation-content/blob/master/swagger/en/matches.yml)。

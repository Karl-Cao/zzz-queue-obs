## 流程

QQ排队：群成员真正 @机器人 /排队 → 公共服务器按群找主播 → 主播电脑HTTPS长轮询接收 → 本地入队或返回当前位 → 回传结果 → 机器人回复。

叫号：主播推进队列 → 本地当前位与TTS更新 → HTTPS发送叫号 → 服务器找已验证UID对应QQ成员（或唯一昵称匹配）→ 在绑定群通知。QQ发送失败不回滚本地叫号，控制台显示错误。

身份验证：QQ /绑定B站 UID → 主播端生成5分钟验证码 → 用户用该B站账号发指定弹幕 → LAPLACE Event Bridge将真实消息交给主播端 → 匹配房间、UID、验证码后保存 → QQ /查看绑定回传已验证结果。

## 当前需注意的事项

1. 本机主播服务仍显示1.12.0-beta.9；源码/package已是1.12.0。更新源码并不意味着运行进程已加载全部改动。
2. v1.12.0发布包早于本次「取消昵称绑定、QQ口令必须带/」修复；公共机器人已加载修复，但旧包生成主播私聊/群绑定提示仍可能不带斜杠。下次发布必须同步更新。
3. 当前Event Bridge虽然连接，但检查时接收事件为0；没有真正收到验证弹幕就无法验证UID。
4. 验证码在主播端内存中，重启后失效；已验证身份持久保存。验证码过期或重启后应重新申请。
5. 本地身份与服务器缓存通过请求回执同步；先完成验证后发送 /查看绑定，可确认并同步结果。换新电脑应迁移data，而不是只保留服务器群绑定。
6. QQ需要群内主动发言权限；主播端与公共服务都必须在线。ZZZ查询仅依赖公共服务器，因此主播电脑离线时查询可能仍可用而排队不可用。
7. 公共服务仍由本机经Cloudflare Tunnel托管；这是服务器角色的临时部署，不代表主播安装包要运行服务器。
8. 两群路由及身份隔离有自动测试，但第二位主播真实设备的全部流程仍需验收。游戏Cookie/账号数据的跨用户隔离尚不能凭队列测试判定完成。
9. 不提供自动QQ红包识别；只有申报并由主播核对入账的流程。部分上游图鉴命令仍未实现，不应通过菜单声称可用。

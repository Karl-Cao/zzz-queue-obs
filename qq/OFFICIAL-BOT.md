# QQ 开放平台官方机器人接入

排队助手使用 QQ 官方机器人接收群内真正的 `@机器人` 消息，再交给本地排队服务或绝区零查询插件处理。无需 NapCat、备用 QQ 登录或 Docker。机器人必须先由群管理员添加到目标群，并在 QQ 开放平台开通**群聊 @ 机器人消息**事件。官方适配器通过 WebSocket 主动连出，通常不需要公网地址或路由器端口映射。[适配器配置说明](https://github.com/nonebot/adapter-qq#配置)

开放平台的「推荐连接指引」列有 WorkBuddy、OpenClaw、Hermes、QClaw、LightVela 和「其他机器人服务」。那些是可选的接入服务，并不要求同时安装。排队助手使用 NoneBot2 的 [QQ 官方适配器](https://github.com/nonebot/adapter-qq)，属于自行接入的方式；不要再把同一个机器人同时接到另一套 Agent 服务。能否收到群消息仍取决于该机器人的开放平台权限和实际连接测试。

1. 在 QQ 开放平台查看机器人的 **AppID** 和 **AppSecret（机器人密钥）**。不要把凭据发到 QQ 群或聊天记录里；如果平台另列 Token，本工具不需要单独填写它。
2. 在直播电脑打开排队助手的设置控制台，找到「QQ 官方机器人 · 绝区零查询」，填入 AppID 与 AppSecret 并保存。凭据只写入本机 `data/qq-runtime/official-bot.json`，网页不会回显。
3. 在「连接与规则」里填写 B 站直播间 ID 与**允许排队的 QQ 群号**，勾选「启用 QQ 群文字排队」。若普通成员要发送文字免费排队，再打开「开启免费排队」。保存后助手自动配置 QQ 排队令牌和当前端口。
4. 点击「启动 QQ 服务」。如果此前正在运行旧版 NapCat 接入，再点「重启 QQ 机器人」切换到官方机器人。状态显示「QQ 机器人已连接」后，再在群里测试。此时不要同时用旧 NapCat 登录同一套机器人服务。
5. 在目标群用 QQ 的真正提及操作选择机器人，先发送一次 `@机器人 排队`。首次发送用于识别该群的 QQ OpenID，可能暂时没有回复。回到控制台点击「刷新收到的 QQ 群」，确认是刚刚测试的群，再点「绑定这个群」。数字群号仍保留在「连接与规则」中。
6. 再发 `@机器人 排队`，现在应回复队列名次；随后可测试 `@机器人 zzz帮助`、`@机器人 zzz刷新面板`。手打昵称文本不算提及；没有 `@` 的群消息不会触发。绝区零查询仍由早柚核心和 ZZZeroUID 处理。

安装包只包含程序与查询插件源码，**不附带大体积的绝区零美术、贴图和攻略图**。需要图片查询时，由主播在解压目录双击 `下载绝区零素材.cmd`，等待下载窗口结束；缺失资源会保存在 `data/qq-runtime/gsuid_core/data/ZZZeroUID/`，升级时随 `data/` 一起迁移。资源下载可能较大，请在网络稳定、有足够磁盘空间时操作；遇到失败可重试，已下载文件会保留。QQ 机器人启动不会自动下载整套素材。尚未下载时，排队功能仍可使用，部分图片查询可能失败或缺图。

完成首次设置后，正常启动排队助手会自动尝试启动 QQ 服务；托盘“重启服务”也会检查它。托盘“退出并停止服务”会停止本安装目录启动的 QQ 进程。若 QQ 服务原本由其他安装目录或旧版手动启动，本助手不会代替它结束进程。

官方接口给排队助手的是群成员 **OpenID**，不是数字 QQ 号。群本身也有独立的 OpenID，因此首次需要绑定。若事件提供昵称，排队助手显示该昵称，并按原有同名规则尝试与 B 站队列合并；若没有昵称，则显示 `QQ用户` 加 OpenID 前六位，无法自动同名合并。绝区零查询由机器人自身权限控制。QQ 红包金额暂不支持自动识别。

仅加入群还不够：测试前请在开放平台确认“群聊 @ 机器人消息”事件可用。如果状态显示服务已运行但机器人未连接，检查 AppID、AppSecret、网络连接和 `data/qq-runtime/startup-logs/nonebot-error.log`。日志含账号信息，不要未经检查直接上传。

`zzz查询`、`zzz深渊` 等米游社查询可能需要账号 Cookie，并可能遇到验证码。`zzz刷新面板`、`zzz练度统计` 等已缓存的公开角色查询可先用于验证插件。不要在群内发送 Cookie、设备信息或验证码。

旧版 NapCat / OneBot 接入说明保留在 [NONEBOT2.md](NONEBOT2.md)，供已有备用账号的用户迁移使用。
